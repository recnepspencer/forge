# Boundary Artifact Taxonomy And Materialization Contracts

This folder documents the Milestone 4 boundary-artifact surface in
`worth-foundational`.

Use these docs when you need to answer questions like:

- How do I describe a boundary output as a summary, report, artifact, or
  receipt without flattening them into one generic envelope?
- How do I make an authoritative claim or a support-only claim without relying
  on prose or conventions?
- How do I plan and materialize a boundary output while keeping seam, cost,
  delivery, availability, and attachment decisions visible?
- How do I canonicalize a materialized boundary output and then strengthen it
  into a current-basis artifact?
- How do planned-work and same-family descriptive outputs stay descriptive
  instead of smuggling Milestone 5 transition meaning in early?
- What exactly is frozen by the Milestone 4 readiness artifact?

Read the docs in this order if you are new to the surface:

1. [Boundary Categories](./boundary-categories.md)
2. [Boundary Roles And Authority Admission](./boundary-roles-and-authority-admission.md)
3. [Boundary Materialization And Bundles](./boundary-materialization-and-bundles.md)
4. [Boundary Canonical Basis And Current-Basis](./boundary-canonical-basis-and-current-basis.md)
5. [Planned Work, Same-Family Outputs, And Reserved Authority Transitions](./planned-work-same-family-and-reserved-authority-transitions.md)
6. [Boundary Production Readiness](./boundary-production-readiness.md)

The order matters.

- Categories come first.
- Roles and authority claims build on categories.
- Materialization and bundle law build on category and role law.
- Canonical basis and current-basis strengthen already-honest materialized
  outputs instead of redefining them.
- Descriptive extensions stay explicitly descriptive and fail closed against
  Milestone 5 authority-transition claims.
- Readiness freezes the machine-checkable closure contract for the milestone.

These docs are capability-first on purpose. They are not milestone notes or
test tours. If a boundary-artifact capability shipped, it should have a stable
home in this folder.
