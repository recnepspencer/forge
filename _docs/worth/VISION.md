Forge: What We're Building and Why It Matters
The specification graph is the product. Not the B-rep, not the mesh, not the rendered image on screen. A Forge model is a directed acyclic graph of features, constraints, and design decisions — serialized as human-readable JSON, committed to git, diffable and mergeable like source code. Two engineers work on different subsystems of a gearbox, branch, build independently, and merge back. The merge is a graph operation on the spec — "both of you added a feature, no conflict" or "both of you changed the same fillet radius, here's the conflict" — not a binary blob collision. The B-rep, the SDF preview, the STEP export are all derived projections of this graph. They can be thrown away and recomputed. The spec is the truth.
This is also what makes Forge native to AI. An agent interacts with the spec graph the same way a developer interacts with code through Claude Code — declarative commands in, structured results out. Create a feature, inspect the decision log, see a warning, extract a minimal reproduction, test a counterfactual, commit the fix. The spec graph is the common language between human engineers, AI agents, and the manufacturing floor. It's what gets versioned, audited, and certified.
The reactive query graph is the skeleton that everything hangs off of. Every computed value in the system — a sketch solution, a surface equation, a Boolean classification, a fillet's geometry — is a node in a dependency graph. Change a parameter and only the affected nodes recompute. Today that means features and geometry. Tomorrow it means "can this beam support this load" as a reactive node that subscribes to the geometry it depends on and updates automatically when the geometry changes. Cost estimation, manufacturability analysis, tolerance stack-up — they're all just nodes in the same graph. This is why the query architecture isn't a performance optimization bolted on later. It's the universal computation backbone that makes parametric CAD, AI interaction, and eventual mechanical simulation all expressions of the same infrastructure.
Every decision the kernel makes is traced. Every classification, every tolerance judgment, every precision escalation, every policy application — recorded as a structured event with a unique ID, a margin metric showing how close it was to the threshold, and full provenance of how it was computed. This isn't developer logging. This is a causal reasoning system that serves three audiences with the same data. For us building the kernel, it's the infrastructure that lets agent swarms continuously find edge cases, extract minimal reproductions, test counterfactuals, and file regression tests — making it possible for a small team to build something that would otherwise take hundreds of engineers. For aerospace and defense, it's the compliance system: a complete, immutable, auditable trace of every geometric decision in a part, from final STEP file back to design intent, replayable and verifiable. No other kernel on the planet can produce this. That's what makes Lockheed say yes. For the broader AI agent ecosystem, it's what makes autonomous design trustworthy — an agent can inspect its own work, identify the riskiest decisions it made, and either resolve them or flag them for human review before anything gets machined.
The geometry engine itself is a hybrid pipeline. For flat-faced geometry — the majority of mechanical parts — Forge uses exact arithmetic where topological decisions are mathematically provable, not approximately correct. For curved geometry — cylinders, fillets, NURBS surfaces — exactness isn't possible, so Forge uses precision escalation with certified bounds, UV-space anchoring that prevents edges from drifting off their surfaces across chained operations, and analytic arbitration that skips the numerical solver entirely when two surfaces have matching definitions. The critical principle is that tolerance exists but is never silent. A tolerant vertex carries a certified error sphere and full provenance of how that sphere was determined. Downstream operations can read it but never silently widen it. Every snap, every merge, every near-boundary classification is a traced decision in the log — the same log that powers the agent debug loop and the aerospace audit trail. The architecture doesn't pretend curved geometry is exact. It makes every approximation visible, bounded, and auditable.
Forge also makes assumptions part of the model instead of leaving them in spreadsheets, consultant notes, or discipline-specific tools. A component is not just reusable geometry; it is a package of geometry, parameters, material behavior, load paths, clearances, routing rules, code assumptions, and resolution policy. Those rules are declared in the spec through a DSL and evaluated by the same reactive query graph as sketches, surfaces, booleans, and tolerances. Change the span, the material, the route, the code basis, the available envelope, or the cost target, and the affected components do not merely turn red for a human to fix later. They re-resolve: framing can resize or re-layout from policy, service runs can negotiate around structure and other systems, assemblies can re-close under weight, strength, clearance, manufacturability, and certification constraints. When the graph cannot close, it does not produce a vague failure; it records which assumption blocked admission, how close the margin was, and which controlled alternatives remain. This is what makes AI-native design more than command automation. An agent can steer intent at the level humans actually care about — cheaper, lighter, easier to manufacture, compatible with this routing zone, still admissible under this rule pack — while the model resolves the component-level consequences and traces every decision. The same mechanism that can coordinate framing and MEP scales to aircraft and industrial systems because the primitive is not a beam or a duct; it is declared design law, reactive resolution, and auditable admission in the spec graph.
