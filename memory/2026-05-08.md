## forge-signal-wasm worker runtime Phase 4

- Continued the worker runtime placement milestone after pulling `origin/master`
  to `80220e45f`.
- Implemented the next Phase 4 batch: a narrow main-thread-hosted callback
  execution boundary with closed worker-issued requests, paired result
  readmission, request digest validation, ambient graph read denial, typed
  failed/denied/unavailable reports, runtime mutation breadth, worker-first
  truth digest, and wasm `SignalWorkerRuntime` facade methods.
- Updated `_docs/forge_signal_wasm/worker_runtime_placement_plan.md` with the
  new Phase 4 evidence and remaining deferrals.
- Continued with a follow-up implementation batch adding hosted callback
  execution certification: Suite 8 evidence now binds placement eligibility,
  replay/import compatibility posture, closed request/result evidence, hosted
  execution digest, and worker-first truth digest, with stale evidence rejection.
- QA loop found and fixed a proof-surface weakness: hosted callback execution
  certification now uses worker-retained request/report evidence instead of
  trusting caller-supplied evidence back through the facade.
- Continued Phase 4 with worker callback capability transport posture:
  `SignalWorkerRuntime` can export/certify runtime-envelope callback
  unavailability artifacts and admit or deny worker runtime-envelope imports
  with typed zero-fallback reports.
- Added the follow-up worker callback reattachment import lane: callback-bearing
  runtime envelopes can be admitted with explicit live callback reattachments,
  while missing or unexpected reattachments are rejected and fallback remains
  zero.
- QA loop tightened the reattachment lane: reattached callbacks must preserve
  the exported read frontier, import reports now bind reattached callback IDs
  into their digest, and rejected/rebuild-failed reattachments dispose callback
  tokens instead of leaking registry entries.
- Continued with the next implementation batch: worker definition-envelope
  publication now has an explicit callback reattachment lane. The default
  portable publication API still denies callback-backed definitions, while the
  opt-in reattachment API admits live callbacks only when they preserve the
  exported read frontier, reports reattached callback ids/host capability
  transport/fallback/truth digest evidence, and disposes rejected or failed
  reattachment tokens.
- Continued with an atomic publication hardening batch: definition-envelope
  publication now preflights ids and dependencies before mutating worker truth,
  so callback-free portable publication and callback reattachment publication
  cannot leave partial sources/callbacks behind after rejection. Reattachment
  preflight rejection now disposes live callback tokens.
- QA loop found and fixed a deeper atomicity issue: publication preflight and
  mutation order disagreed for recipes that read reattached callbacks and for
  recipe-family reads. The fix introduced an explicit publication dependency
  plan, split planning into its own module to preserve line caps, added blocked
  read diagnostics, and preflights invalid recipe read aspects before mutation.
- Continued with a Phase 4 batch exposing multi-callback reattachment through
  the wasm worker facade. Runtime-envelope import and definition-envelope
  publication now have JS array batch methods while preserving scalar wrappers,
  and worker-host tests prove multiple reattachments are admitted through both
  lanes.
- Continued with a Phase 4 closeout certification batch: worker runtime shells
  now retain current import/publication evidence and expose
  `certifyWorkerCallbackPhase4Closeout`, which binds placement digests,
  zero-fallback import/publication evidence, callback counts, current worker
  truth, and a closeout digest while rejecting missing or stale evidence.
- QA tightened Phase 4 closeout certification: the package now names its
  `PublicationReattachmentWithPortableImportDenial` gate mode, exposes import
  and publication outcomes, requires callback-bearing portable import denial
  plus callback reattachment publication evidence, and rejects weaker
  non-callback zero-fallback publication evidence.
- Began Phase 5 with committed worker observation delivery. Added
  `deliverLatestObservation` and `certifyWorkerObservationDelivery`, a typed
  `observationDelivery` packet with delivery breadth/performance/truth/digest
  evidence, retained-packet certification, and tests for committed delivery,
  missing observation evidence, and cleared stale delivery evidence.
- Continued Phase 5 with committed worker output delivery. Added
  `deliverOutputs({ outputIds })` and `certifyWorkerOutputDelivery`, a typed
  `outputDelivery` packet with output values, delivery breadth, payload byte
  breadth, performance/truth/digest evidence, retained-packet certification,
  and tests for happy-path delivery plus empty, duplicate, unknown, and cleared
  delivery evidence rejection.
- QA tightened output delivery honesty: worker portable graph publication now
  carries validated `outputIds`, marks those recipes as public outputs only
  after successful publication, rejects source/non-recipe output roles before
  mutation, and `deliverOutputs` now refuses arbitrary non-output signal ids.
- Continued Phase 5 with diagnostics/history read cost honesty. Added worker
  `readDiagnosticsSummary`, `readDiagnosticsHistory`, and
  `certifyWorkerDiagnosticsSummaryRead`; summary reads now emit stable
  diagnostics summary and rich-read availability digests with zero cold
  reconstruction, while rich history reads carry separate cold-work
  attribution.
- Continued Phase 5 with worker lifecycle/disposal control. Added
  `attachObservationDelivery`, `detachObservationDelivery`, and
  `certifyWorkerLifecycleControl`; public observation delivery now requires an
  active worker-owned lifecycle subscription, detach emits typed
  `lifecycleControl` evidence, and unknown detach ids produce denial artifacts
  without mutating worker truth.
- QA tightened the lifecycle/delivery proof: observation delivery packets now
  carry the active lifecycle subscription count and canonical lifecycle digest,
  and certification revalidates both so detach or observer-set churn invalidates
  stale delivery certification.
- Continued Phase 5 with a closeout certification lane. Added
  `certifyWorkerPhase5Closeout` to bind retained observation delivery, output
  delivery, diagnostics summary read, current worker truth, active lifecycle
  digest, delivery breadth, and boundary performance into one Phase 5 proof
  package with rejection tests for missing evidence, mutation-cleared evidence,
  lifecycle churn, and detached lifecycle.
- Began Phase 6 with same-runtime branch restore capability certification.
  Added worker branch create/switch/snapshot facade methods plus
  `restoreBranchSnapshotWithCapabilityReport` and
  `certifyWorkerReplayRestoreCapability`; reports bind snapshot, replay/restore,
  restored branch truth, placement identity, capability availability, exact
  restore artifact, and zero fallback, with tests for missing evidence,
  mutation-cleared evidence, and capability churn after restore.
- QA tightened the Phase 6 replay/restore proof surface: restore reports and
  certification now also bind replay/import compatibility and lowered-plan
  identity digests, and certification revalidates lowered-plan identity against
  the current capability posture instead of relying on restored values alone.
- Continued Phase 6 with Suite 13 import/export callback unavailability
  certification. Worker shells now retain callback-unavailability export,
  portable import denial, and same-runtime callback reattachment import evidence
  as one historical sequence, then certify export/import/reattachment digests,
  callback-unavailability artifacts, host-capability transport count, and zero
  fallback while rejecting missing or weak evidence.
- Continued Phase 6 with Suite 12 checkpoint-plus-retained-history replay
  certification. Worker shells now retain checkpoint replay evidence, bind
  checkpoint/full replay/retained history/replay-restore digests plus current
  capability and lowered-plan identity, expose record/certify facade methods,
  and reject missing, stale, cross-branch, or empty-suffix checkpoint evidence.
- QA tightened the Suite 12 checkpoint replay certification: the package now
  names the exact checkpoint-plus-retained-history restore artifact, branch
  creation and snapshot capture clear stale historical evidence, and tests
  cover capability churn plus branch/snapshot topology churn after evidence
  capture.
- Continued Phase 6 with no-worker compatibility artifact certification.
  `SignalDiagnostics.workerUnavailableCompatibilityCertification` now proves
  explicit main-thread compatibility posture for environments without worker
  support, binding compatibility truth convergence, deployment/fallback policy,
  historical capability posture, replay/import compatibility, placement identity,
  `dedicatedWorkerUnavailable` incompatibility, and zero hidden fallback while
  rejecting non-convergent compatibility truth.
- QA tightened the no-worker compatibility package: it now exposes and binds
  concrete placement denial/fallback digests plus callback classification

- Continued Phase 6 with a closeout certification bundle. Worker shells now
