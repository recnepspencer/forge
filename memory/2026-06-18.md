## Forge Query 9.9 Phase 3 QA

- Ran the QA loop for graph obligation registration, touch selectors, and
  operating-world binding.
- Corrected Phase 3 semantics: graph obligation conflicts are now scoped to
  rule identity plus touch selector plus operating-world selector, so the same
  rule identity can bind multiple real lanes while contradictory same-slot
  registrations still fail.
- Added registration constructors for every graph obligation kind and explicit
  custom invariant-to-graph-obligation registration that requires a declared
  touch selector instead of pretending Query can infer closure scope.
- Replaced schema-contract relation-kind auto-lowering with a typed
  relation-kind-id selector rather than a collection-shaped string.

## Forge Query 9.9 Phase 4 QA

- Hostile QA found Phase 4's index selection counters were not enough by
  themselves: the phase required named complexity contracts, not just tests
  that implied a performance claim.
- Added digest-backed graph obligation index complexity contracts for index
  build and dispatch selection, and exposed attempted bucket lookup counts so
  no-match lookups cannot under-report selection work.

## Forge Query 9.9 Phase 6

- Integrated graph obligation dispatch into authoritative mutation batch

  hop, ordinary command batches use the authoritative-command-batch dispatch
