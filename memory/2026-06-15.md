# 2026-06-15

- Worth UI M4 Phase 1 QA fixed two real gaps: the validation app had
  registered Worth UI theme tokens but rendered from a duplicate raw egui
  palette, and the shell frame snapshot was not tied tightly enough to the
  render surface contract. The app now derives its render theme from prepared
  `ThemeTokenDescriptor` values, carries density/latest receipt state through
  navigation, and renders from the stable shell surface manifest.
- Worth UI M4 Phase 1 test/code QA strengthened the suite and structure:
  split shell tests from web-artifact guard tests, added token-derivation and
  native-webview dependency denial coverage, declared embedded shell surface
  render parents, and split `shell/frame.rs` into frame orchestration,
  snapshot inspection, and egui surface rendering responsibilities.
- Worth UI M4 Phase 2 implemented the native Surface Atlas workbench page
  inside `apps/worth-ui-validation-app`. It uses the existing prepared launch,
  runtime summary, visual foundation receipt, density, and harness evidence
  APIs; adds explicit atlas topology, sample-only fixture evidence, viewport
  reachability, and region renderers; and adds hostile tests for required
  surface-family coverage, sample-only evidence honesty, no synthesized runtime
  receipts, theme/density invariance, and narrow viewport access.
- Worth UI M4 Phase 2 QA found and fixed two substantive gaps: the atlas
  topology listed required surface families that were not all explicitly
  rendered, and the page was rebuilt from launch during frame rendering. The
  shell now owns the initialized atlas page, render consumes current runtime
  summary by reference, the atlas model no longer stores copied runtime truth,
  required families have visible region renderers, fixture evidence display no
  longer allocates a Vec per frame, and the topology test file was renamed away
  from phase/provenance naming.
- Worth UI M4 Phase 2 test/code-quality QA found that the topology test still
  trusted a parallel visible-family list beside the render body. The page now
  renders through a single `SurfaceAtlasRenderPlan`; tests inspect the same
  plan family projection used by rendering, and the plan models one theme/density
  control renderer covering both required surface families without duplicate UI
  rendering.
- Worth UI M4 Phase 3 implemented the validation-app honesty boundary. The app
  now has a narrow `honesty` module for public-facade launch preparation and
  runtime-backed evidence gating, integration tests proving app-local shell
  injection, visual-only success, and stale previous-step receipts are rejected,
  and trybuild pass/fail fixtures proving public facade launch compiles while
  internal runtime/capability imports, pre-minted run receipts, and direct
  evidence-family injection fail at compile time.
- Worth UI M4 Phase 3 QA tightened the honesty boundary: `honesty` now exposes
  only a narrow facade instead of public submodule topology, and compile-fail
  probes now explicitly cover active-plan and diagnostics internals in addition
  to runtime and capability/registry internals. The diagnostics fixture was
  corrected to fail only on the intended private-module boundary.
- Worth UI M4 Phase 3 test/code-quality QA found one real stale-proof gap:
  the validation app evidence gate accepted aggregate receipt evidence, which
  could let a final visual-only completion borrow runtime proof from an earlier
  setup step. The gate now checks runtime and active-plan evidence on the
  completed step in the harness evidence ledger, and the test suite includes a
  hostile stale-aggregate receipt case that would have exposed the old bug.
